# Приёмочный план Aegis

Проверять на копии проекта и только с вымышленными данными. Не использовать
рабочие пароли и не копировать реальные `Aegis.db`, ключи или журналы в тестовую
среду. Для GUI-проверок запускать EXE из каталога, доступного для записи.

Статус фиксируется как `PASS`, `FAIL` или `NOT RUN`; не заменять `NOT RUN`
предположением по результатам unit-тестов.

## Автоматические проверки

Текущий запуск: `python -B -m unittest discover -s tests -v` — 13 тестов проходят.

- [x] AES-GCM round-trip, отказ с неправильным паролем и отсутствие plaintext.
- [x] Аутентификация параметров KDF в заголовке.
- [x] Чтение старого формата `[salt][nonce][ciphertext]`.
- [x] Раздельные файлы аккаунтов и отказ открыть чужой файл другим паролем.
- [x] Пошаговая миграция одного аккаунта с сохранением источника.
- [x] Смена пароля меняет только выбранный аккаунт.
- [x] Чтение записей выполняется из пространства выбранного аккаунта.
- [x] Резервное копирование старого общего хранилища в текущий сеанс извлекает только активный аккаунт.
- [x] CSV round-trip и отказ от файла без нужных колонок.
- [x] Блокировка повторного процесса и освобождение lock-файла.
- [x] Атомарная запись не оставляет временный файл после успешного сохранения.
- [x] Ошибка атомарной замены сохраняет прежнюю базу и удаляет временный файл.

## Ручная проверка GUI/EXE — ещё не запускалась

### Установка и запуск

- [ ] Распаковать `dist\Aegis` в каталог с правом записи.
- [ ] Запустить `Aegis.exe`; убедиться, что появляется окно входа и рядом создаётся
      только lock-файл/журнал, без пустого аккаунта или незашифрованной базы.
- [ ] Запустить второй экземпляр из того же каталога; убедиться, что он сообщает
      о первом экземпляре и не открывает второе окно.
- [ ] Закрыть первый экземпляр; повторный запуск должен работать.

### Аккаунты и хранилища

- [ ] Создать аккаунт `demo-a` с отдельным тестовым мастер-паролем длиной от 12
      символов и добавить вымышленную запись.
- [ ] Выйти, создать `demo-b` с другим мастер-паролем; проверить пустое хранилище.
- [ ] Проверить, что пароль `demo-b` не открывает `demo-a`, и наоборот.
- [ ] Сменить пароль `demo-a`; проверить, что `demo-b` по-прежнему открывается
      старым собственным паролем, а `demo-a` — только новым.
- [ ] Создать две записи, проверить URL, категорию, заметки, поиск, редактирование,
      удаление и отсутствие потери изменений после перезапуска.
- [ ] Проверить сохранение и повторное открытие при символах Unicode в паролях,
      именах аккаунтов, заметках и путях каталогов.

### Буфер, блокировка, сеть

- [ ] Скопировать тестовый пароль, дождаться таймера очистки и убедиться, что
      чужое содержимое, скопированное позже, не стирается.
- [ ] Скопировать пароль и сразу выйти/закрыть окно; проверить очистку буфера.
- [ ] Установить минимальный допустимый idle timeout, подождать и проверить
      блокировку; проверить, что ввод/нажатия сбрасывают таймер.
- [ ] Отключить HIBP и убедиться, что автоматических сетевых запросов нет.
- [ ] Включить HIBP, проверить результат при сети и корректное сообщение без
      сети; не использовать реальный пароль.

### Импорт, экспорт, резервирование и миграция

- [ ] CSV импортирует корректные строки, отказывает при отсутствии колонок,
      корректно обрабатывает Unicode и пустые обязательные поля.
- [ ] CSV экспорт показывает предупреждение об открытых паролях; повторный
      импорт экспортированного тестового файла восстанавливает данные.
- [ ] Создать зашифрованную резервную копию, удалить тестовую запись и восстановить
      её; проверить отказ для неверного мастер-пароля.
- [ ] На отдельной копии старого формата войти в один legacy-профиль; проверить,
      что создаётся ровно один новый файл, исходный `Aegis.db` остаётся, остальные
      аккаунты ещё могут быть перенесены.
- [ ] Восстановить старый формат с неверным паролем и проверить, что источник не
      изменяется.
- [ ] Завершать миграцию только после сверки всех legacy-профилей и внешней копии.

### Ошибки и сбои

- [ ] Проверить поведение при повреждённом заголовке/ciphertext: приложение не
      перезаписывает источник и сообщает, что файл нельзя открыть.
- [ ] Остановить тестовый экземпляр во время сохранения; файл должен быть либо
      старой, либо новой полной версией, не частичным ciphertext.
- [ ] Проверить блокировку после неудачных входов, отключённый fail2ban и сброс
      счётчика при успешном входе.
- [ ] Проверить, что self-destruct удаляет только активный файл выбранного аккаунта
      и ясно сообщает, что копии/legacy-файл остаются.

## Критерий допуска к защите

Все пункты GUI/EXE должны иметь зафиксированный результат, а блоки
«Аккаунты и хранилища», «Резервирование и миграция», «Ошибки и сбои» должны быть
`PASS`. Сохранить дату, версию EXE, ОС, исполнителя проверки и краткое доказательство
(скриншот без секретов или ссылку на тестовый отчёт).
