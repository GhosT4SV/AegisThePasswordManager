# Черновой каркас дипломной работы

Текст ниже — техническая основа, а не готовое оформление по методичке кафедры.
Формальные требования, список источников и результаты ручных испытаний нужно
добавить по правилам учебного заведения.

## Предлагаемая тема

«Разработка локального менеджера паролей с раздельными зашифрованными
хранилищами пользователей».

## Цель, объект и предмет

- **Цель:** разработать и проверить настольное приложение для локального
  хранения учётных данных с независимой криптографической защитой аккаунтов.
- **Объект:** процесс локального управления учётными данными пользователя.
- **Предмет:** методы шифрования, управления мастер-паролями, хранения,
  резервирования и миграции данных в настольном приложении.

## Задачи

1. Определить функциональные требования и модель угроз.
2. Спроектировать формат зашифрованного контейнера и вывод ключа из
   мастер-пароля.
3. Реализовать отдельный файл хранилища для каждого аккаунта.
4. Реализовать операции над записями, генератор паролей, резервное копирование,
   CSV-обмен и пошаговую миграцию старой базы.
5. Проверить корректность хранения автоматическими и ручными испытаниями.
6. Подготовить portable-сборку и пользовательскую документацию.

## Проверяемые проектные решения

- Argon2id выводит 256-битный ключ из мастер-пароля и случайной соли.
- AES-256-GCM обеспечивает конфиденциальность и проверку целостности; заголовок
  параметров KDF аутентифицируется как associated data.
- Для аккаунта `u` файл называется по SHA-256 имени аккаунта и содержит только
  его профиль. Само имя аккаунта не используется как имя файла.
- Смена мастер-пароля одного аккаунта сохраняет его файл отдельно и не требует
  перешифрования хранилищ остальных аккаунтов.
- Миграция переносит один профиль за успешный вход и сохраняет исходную общую
  базу до ручной проверки переноса.

## Предлагаемая структура записки

1. Анализ задачи и требований к локальному менеджеру паролей.
2. Модель угроз и выбор криптографических примитивов.
3. Архитектура, формат данных и интерфейс приложения.
4. Реализация хранения, аккаунтов, импорта, экспорта и резервирования.
5. Испытания, анализ результатов и ограничения.
6. Руководство пользователя и выводы.

## Текущее доказательство реализации

- 13 автоматических тестов покрывают криптографический round-trip, отказ при
  неверном пароле, аутентификацию заголовка, разделение аккаунтов, миграцию,
  CSV и атомарную запись, включая искусственный отказ замены.
- Сборка `onedir` создаётся PyInstaller; версия EXE и SHA-256 зафиксированы в
  `BUILD.md`.
- Ручная проверка GUI/EXE пока `NOT RUN`; автоматические тесты не заменяют её.

## Что собрать для финальной защиты

- Утверждённое название темы и формальные требования руководителя/кафедры.
- Скриншоты интерфейса только с вымышленными тестовыми данными.
- Подписанный протокол ручной приёмки с ОС, версией EXE, датой и исполнителем.
- Результаты восстановления резервной копии, миграции legacy-аккаунтов,
  изоляции аккаунтов и поведения при ошибках записи.
- Список официальных документаций и стандартов, использованных при обосновании
  криптографии и модели угроз.
- Отдельный анализ ограничений: открытая память процесса, вредоносное ПО,
  доступность файлов, сетевые метаданные HIBP, незашифрованный CSV и копии.
